# `data/seeds/` — checked-in ingestion inputs

Pinakes builds its index from live data sources (CrossRef, OpenAlex, RSS, scrapers). For a few journals/publishers, intermediate JSON or CSV files were generated once and committed so the canonical record of what was ingested travels with the repo. They are inputs to one-off ingestion scripts at the project root, not to the live web app.

|---|---:|---|---|---|

| `ccdp_scraped.json` | 78 KB | 2026-04-07 | [`scrape_ccdp.py`](../../scrape_ccdp.py) (Computers and Composition Digital Press catalogue scraper) | Reviewed by hand, then ingested via the same script's load step |
| `jac_articles.csv` | 362 KB | 2026-05-23 | CompPile export of *JAC* records: 1,224 rows, 1980–2014, vols 1–34 (*JAC* never deposited DOIs) | [`ingest_jac.py`](../../ingest_jac.py) |
| `rpc_4_1.json` | 51 KB | 2026-10-12 | Harvested from the MUSE article pages' `citation_*` meta tags for *Rhetoric, Politics & Culture* 4.1 (never deposited in CrossRef) | [`ingest_rpc_4_1.py`](../../ingest_rpc_4_1.py) |

## Re-running

- **`peer_review_references.json`** is hand-curated. The script `ingest_peer_review_1_1.py` reads it as-is; there is no producer to re-run. Edit the JSON directly if a reference needs to be corrected, then re-run the ingest script (which is idempotent — it uses INSERT-OR-IGNORE on `(source_article_id, target_doi)`).
- **`jac_articles.csv`** is a one-time CompPile export; there is no script that regenerates it. `ingest_jac.py --dry-run` reports what would change without writing; without the flag it applies. It is idempotent: rows are keyed on a synthetic `jac:` URL built from volume, issue, first page, first author's surname and a title slug, and existing rows are skipped.
- **`rpc_4_1.json`** is a one-time harvest; MUSE sits behind a CAPTCHA, so there is no scraper to re-run. Re-running `ingest_rpc_4_1.py` is idempotent (articles keyed on the MUSE URL; each article's citations are wiped and re-inserted).
- **`ccdp_scraped.json`** can be regenerated by re-running `python scrape_ccdp.py` from the repo root. The scraper is rate-limited (5 s between requests) and respects CCDP's robots.txt. Output is written back to this same path.

## Why these files are committed

These are small (the largest, `jac_articles.csv`, is under 400 KB), human-readable, and form part of the bibliographic provenance: anyone who wants to audit which references the index attributes to *Peer Review* 1.1 can read [peer_review_references.json](peer_review_references.json) directly. Treating them as repository data rather than build artefacts is intentional.

## What does NOT belong here

- Output databases (`articles.db`, `*.sqlite`) — gitignored; in production the database lives on the Windows server (`C:\Pinakes\data\` by default).
- Bulk fetch responses from CrossRef / OpenAlex — fetched at runtime by `fetcher.py` / `enrich_openalex.py` and never written to the repo.
- Anything containing PII, API keys, or non-public material.
